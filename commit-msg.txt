feat: PT 流量改为原生整合（去掉 iframe），按功能拆分到各页面

前一版只是把 Go 的整页面板用 iframe 套进来，用户仍在两套界面之间
切换，主题、导航、交互都不一致——那不叫整合。

本次改为：Python 调用 Go 的 JSON API，用 PTtools 自己的 UI 渲染。

## 界面重新分配

| 原 Traffic Guard | 现在的位置 |
|---|---|
| 总览（速率、在线数） | 仪表盘顶部指标卡 |
| 策略进度与限速状态 | 侧边栏「PT 策略」 |
| 下载器明细与连通测试 | 侧边栏「PT 策略」 |
| 事件（触发/解除限速） | 侧边栏「事件日志」（与 CD2/115 合并） |
| 配置（客户端/策略/通知） | 系统设置 → PT 流量监控 |

侧边栏命名从「BT 流量」改为「PT 策略」。

## 后端

- 新增 app/api/pt.py：原生数据接口
  GET  /api/pt/overview|clients|policies|events|config|history
  POST /api/pt/policy/{resume|trigger}
  PUT  /api/pt/config    （YAML 原文，保存后热重载）
- BTGuardManager 增加数据访问方法：fetch_status / fetch_events /
  fetch_config_yaml / save_config_yaml / policy_action / test_client
- 配置用 YAML 原文而非逐字段映射：Go 侧字段多，映射易漏且易随版本漂移
- 仪表盘 /api/dashboard 增加 pt 字段；子服务不可用时 available=false，
  不影响整页渲染
- 新增 scheduler._import_pt_events：把 PT 策略事件汇入统一 event_logs，
  带签名去重与有界集合，侧边栏事件日志一处可见全部事件

## 前端

- 删除 iframe，新增原生「PT 策略」页：速率卡片、策略进度条、
  解除限速/手动触发、下载器明细与连通测试
- 仪表盘按需追加 2 张 PT 卡片（仅子服务运行时显示，避免误导）
- 系统设置新增「PT 流量监控」卡片：YAML 编辑器 + 载入/模板/保存/重启，
  并保留「打开原始面板」作为排错入口
- 页签键 bt 改为 pt，写入 URL hash

## 测试

新增 tests/test_pt_native.py（12 个）：原生接口齐全、仪表盘含 pt、
优雅降级、事件汇入与去重、侧边栏命名、无 iframe、页签键名。

10 个套件 128 个测试全部通过。
